Simplification de forme

Réduire le nombre de points d'un tracé sans perdre sa silhouette
Algorithme de Ramer-Douglas-Peucker appliqué aux courbes de l'éditeur
Animate JS (TweenJS) · Octobre 2026 · Licence CC BY-NC 4.0

1. Le problème à résoudre

Un tracé dessiné à la Plume ou importé depuis un SVG contient souvent des points d'ancrage redondants : des sommets presque alignés qui n'apportent rien à la silhouette visuelle mais alourdissent le document. Le but de la simplification est double :

  • réduire le nombre de points (fichier plus léger, édition plus simple) ;
  • garder la forme reconnaissable — la silhouette simplifiée doit rester dans un rayon ε (la tolérance) de la forme d'origine.

Dans l'éditeur, la fonctionnalité se présente dans le Panneau Propriétés d'une forme de type ligne ou tracé sélectionnée : un bouton « Simplifier la forme » (tolérance 1.0 par défaut) et un champ Tolérance avec le bouton « Simplifier avec » pour choisir son ε.

2. Pourquoi Ramer-Douglas-Peucker

Plusieurs familles d'algorithmes existent pour décimer une polyligne. Le choix s'est porté sur Ramer-Douglas-Peucker (RDP, 1973) pour trois raisons :

  1. Garantie mathématique : tout point supprimé se retrouve à une distance ≤ ε du contour simplifié. L'erreur visuelle est donc bornée par construction, ce qui n'est pas le cas des méthodes de décimation par pas (garder 1 point sur N) ou des seuils d'angle.
  2. Extrémités conservées : le premier et le dernier point d'un tracé ouvert ne sont jamais supprimés — indispensable pour que les tracés raccordés à d'autres restent raccordés.
  3. Simplicité : une vingtaine de lignes récursives, aucun état, aucune dépendance, testable sous Node.
    4. Performance. RDP est en O(n log n) en moyenne et O(n²) au pire cas (points répartis uniformément). Pour des tracés d'éditeur (quelques centaines de points au plus), c'est instantané.

    L'implémentation est un portage adapté de simplify.js du projet __IIB.v.3 (lissé + RDP, testé unitairement), réécrite pour manipuler directement les PathPoint de ce projet — voir chapitre 5.

    3. Le cœur de l'algorithme

    3.1 La distance point-segment (et pas point-droite)

    La brique de base est la distance entre un point P et le segment AB — pas la droite infinie AB. Un point situé « après » B doit être mesuré par rapport à B, pas projeté au-delà :

    function distToSeg(px, py, ax, ay, bx, by) {
  const dx = bx - ax, dy = by - ay;
  const l2 = dx * dx + dy * dy;
  let t = l2 ? ((px - ax) * dx + (py - ay) * dy) / l2 : 0;
  t = Math.max(0, Math.min(1, t));          // projection clampée sur [0,1]
  return Math.hypot(px - (ax + t * dx), py - (ay + t * dy));
}

    Le paramètre t projette P sur la droite AB ; le clamp garantit que la mesure tombe sur le segment. Cas dégénéré l2 = 0 (A et B confondus) : la distance est simplement celle de P à A.

    3.2 La récursion RDP (tracé ouvert)

    Le principe : entre les extrémités A et B du tracé, on tend une « corde ». On cherche le point le plus éloigné de cette corde :

    • si dmax > ε : ce point est un sommet significatif — on le garde, et on relance la récursion sur les deux sous-tronçons [A..point] et [point..B] ;
    • si dmax ≤ ε : tous les points intermédiaires sont remplacés par le segment droit AB.
    function rdpOpen(pts, eps) {
  if (pts.length < 3) return [...pts];
  const A = pts[0], B = pts[pts.length - 1];
  let dmax = -1, index = -1;
  for (let i = 1; i < pts.length - 1; i++) {
    const d = distToSeg(pts[i].x, pts[i].y, A.x, A.y, B.x, B.y);
    if (d > dmax) { dmax = d; index = i; }
  }
  if (dmax > eps) {
    const left  = rdpOpen(pts.slice(0, index + 1), eps);
    const right = rdpOpen(pts.slice(index), eps);
    return left.slice(0, -1).concat(right);   // le point pivot est partagé
  }
  return [A, B];
}
    Concrètement : une succession de points alignés s'effondre en 2 extrémités ; un « pic » qui dépasse ε de la corde survit et devient un sommet. Plus ε est grand, plus il faut de l'ampleur pour survivre — d'où le réglage par le champ Tolérance.

    3.3 Le cas fermé : découper l'anneau

    Un contour fermé (rempli) n'a pas d'extrémités naturelles : la récursion ouverte n'a pas de corde évidente sur laquelle s'appuyer. La solution :

    1. prendre le point 0 et le point k le plus éloigné de lui (une approximation du « diamètre » de la forme, en O(n)) ;
    2. cette paire découpe l'anneau en deux chaînes ouvertes : [0..k] et [k..0] ;
    3. appliquer rdpOpen sur chacune, puis recoller les résultats en retirant les doublons aux jointures.
    function rdpClosed(ring, eps) {
  const n = ring.length;
  if (n < 5) return [...ring];
  // point le plus éloigné du point 0
  let k = 1, dmax = -1;
  for (let i = 1; i < n; i++) { /* ... */ }
  const ra = rdpOpen(ring.slice(0, k + 1), eps);
  const rb = rdpOpen(ring.slice(k).concat([ring[0]]), eps);
  const out = ra.slice(0, -1).concat(rb.slice(0, -1));
  return out.length >= 3 ? out : [...ring];   // garde-fou : ≥ 3 sommets
}

    Le garde-fou final garantit qu'un polygone fermé ne descend jamais sous 3 points — sous peine de ne plus rien délimiter.

    3.4 Le lissage préalable (optionnel)

    Avant la décimation, l'API accepte smoothPasses passes de moyenne mobile pondérée (poids 1-2-1 sur les voisins, normalisés par 4) :

    q[i] = (p[i-1] + 2*p[i] + p[i+1]) / 4
    • Chaîne ouverte : les extrémités restent figées, seuls les points intérieurs bougent ;
    • Anneau : la moyenne est cyclique (wrap-around), le point 0 a pour voisins les points n-1 et 1.
    Choix de l'éditeur. Le panneau Propriétés appelle la simplification avec smoothPasses = 0 : aucun point n'est déplacé, seuls des points redondants disparaissent. Le lissage est disponible dans l'API (simplifyPathPoints(pts, ε, fermé, passes)) pour un usage futur — par exemple lisser un tracé au pinceau avant de le simplifier.

    4. Adaptation aux courbes de l'éditeur

    C'est la partie où l'algorithme générique rencontre le modèle de données du projet. Un point d'ancrage de tracé n'est pas un simple [x, y] :

    { x, y, cIn, cOut, smooth }
    • x, y — position de l'ancre, relative à l'origine de la forme (shape.x/y) ;
    • cIn, cOut — vecteurs des poignées de Bézier, relatifs à l'ancre (ou null : point anguleux) ;
    • smooth — l'outil sous-sélection déplace alors cIn et cOut en miroir.

    4.1 La décision clé : les poignées sont supprimées

    Le point le plus important de l'implémentation : les points conservés par RDP perdent leurs poignées (cIn = cOut = null, smooth = false), et le tracé simplifié devient une polyligne d'ancres. Pourquoi ce choix :

    1. RDP classifie les points en « sommet significatif / point redondant ». Les anciennes poignées décrivaient la courbure du tracé d'origine : réattacher telles quelles des poignées pensées pour d'autres voisins produirait des arcs incohérents (des boucles, des dépassements) sur la nouvelle polyligne.
    2. Calculer de nouvelles poignées fidèles serait un problème de fitting de courbe (cf. pistes d'amélioration) — un algorithme différent, itératif, hors du périmètre de cette fonctionnalité.
    3. La garantie de RDP porte sur les ancres : tout point supprimé est à ≤ ε de la polyligne joignant les ancres conservées. La promesse « la silhouette ne bouge pas de plus de ε » reste ainsi exacte et vérifiable.
    Conséquence visuelle : sur un tracé très courbé, une tolérance élevée remplace des arcs par des segments légèrement anguleux. C'est le compromis explicite de la fonction : ε contrôle le rapport « nombre de points vs rondeur ». Une tolérance fine (0.3–0.5) ne touche que le bruit redondant et préserve la sensation de courbe.

    4.2 Ce qui ne bouge pas

    • Les points étant relatifs à l'origine de la forme, la simplification ne modifie ni shape.x/y, ni la position apparente de l'objet sur la scène ;
    • shape.closed pilote la variante d'algorithme (anneau ou chaîne ouverte) ;
    • toutes les autres propriétés (remplissage, contour, opacité, calque...) sont inchangées — seule la liste points est remplacée.

    5. L'API (src/util/simplify.js)

simplifyPathPoints(pts, tolerance, closed, smoothPasses = 0)

// Enveloppe pour éléments : refuse tout ce qui n'est pas line/path
// ou qui a moins de 2 points (la forme est renvoyée telle quelle)

    5.1 Intégration dans le panneau Propriétés

    • Les contrôles n'apparaissent que pour une forme line ou path avec au moins 2 points ;
    • la mutation passe par mutateSelectedElement() → elle est annulable (Ctrl+Z) et posée sur l'image clé courante comme toute édition ;
    • si la tolérance ne retire aucun point, un message l'explique au lieu de semblant ne rien faire ;
    • en cas de résultat sous le minimum (tracé trop court), la fonction renvoie le tracé d'origine sans ses poignées — jamais un tracé invalide.

    6. Bien choisir sa tolérance

    ToléranceEffetUsage typique
    0.3 – 0.5Ne retire que les points quasi redondantsNettoyage fin, préparation au morphing
    1 – 2Équilibre points / fidélité (défaut : 1.0)Simplification standard d'un tracé Plume
    3 – 5Forte décimation, arcs → segments visiblesSilhouettes volontairement anguleuses, allègement massif
    > 5Seules les grandes aspérités surviventRéduire une courbe à son « squelette »
    Le bonus morphing. Le morphing de l'éditeur apparie les points par index (1er avec 1er, 2e avec 2e...) et ne se déclenche que si deux images clés contiennent le même nombre de points. Simplifier deux courbes avec la même tolérance tend à aligner leurs densités de points — et surtout, une courbe simplifiée est plus facile à retoucher à l'outil sous-sélection pour tomber exactement sur le bon compte avant de créer l'image clé suivante.

    7. Pistes d'amélioration

    • Fitting de Bézier (Schneider, 1990) : au lieu de conserver les ancres telles quelles, ajuster des segments de Bézier cubiques sur les points supprimés — la forme simplifiée resterait courbe. C'est l'évolution naturelle si les polylignes anguleuses deviennent gênantes ;
    • Tolérance relative : exprimer ε en pourcentage de la boîte englobante du tracé, pour qu'un même réglage « se sente pareil » sur une petite et une grande forme ;
    • Shape hints : laisser l'utilisateur épingler des points qui ne doivent jamais être supprimés (appariement de morphing guidé, comme dans Animate CC) ;
    • Prévisualisation : un curseur montrant en direct le résultat et le nombre de points conservés avant de valider.
