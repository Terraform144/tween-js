Coder avec TweenJS

Travailler sur un projet TweenJS depuis un éditeur de code externe
Scripts de MovieClip, fichiers .js externes et intégration VS Code
Animate JS (TweenJS) · Octobre 2026 · Licence CC BY-NC 4.0

1. Le principe général

Dans Adobe Animate CC, les gros projets ActionScript 3 reposent sur une séparation nette : l'éditeur visuel s'occupe du dessin et de la timeline, et le code vit dans des fichiers .as séparés, édités dans un vrai éditeur de code. TweenJS reprend cette séparation :

  • Le panneau Scripts de l'application reste le point d'entrée : c'est lui qui détient le code de chaque script et qui l'exécute pendant la lecture.
  • Chaque script (celui de la scène principale comme celui de chaque MovieClip) peut être externalisé dans un fichier .js que vous éditez où vous voulez — typiquement dans Visual Studio Code.
  • Les boutons Importer, Exporter, VS Code et Lier du panneau Scripts font la navette entre votre éditeur et l'application.
Ce qu'un navigateur peut et ne peut pas faire. Une application web ne peut ni lancer un programme de votre poste, ni surveiller un dossier du disque en arrière-plan. TweenJS contourne honnêtement ces limites avec trois mécanismes universels (import de fichier, téléchargement, protocole vscode:// de VS Code) et un mécanisme avancé — la relecture automatique — réservé aux navigateurs Chromium (Chrome, Edge, Vivaldi) via la File System Access API.

2. Le script de MovieClip : votre « classe AS3 »

2.1 Où le trouver

Chaque symbole de type MovieClip possède son propre script — l'équivalent d'une classe AS3 attachée au clip. Pour l'éditer :

  1. Dans la Bibliothèque, double-cliquez le MovieClip pour entrer dans son contexte d'édition (ou ouvrez une instance sur scène et double-cliquez-la).
  2. Dans le panneau Scripts, un bouton MovieClip : <nom> apparaît (entre les onglets de scripts et les scripts d'image).
  3. Cliquez dessus : l'éditeur de code bascule sur le script du symbole, prérempli avec un squelette de constructeur.

2.2 Quand s'exécute-t-il ?

Le script de MovieClip est un constructeur d'instance :

  • Il s'exécute UNE seule fois par instance, au démarrage de la lecture — deux instances du même symbole exécutent chacune le script, avec un état indépendant.
  • Il s'exécute avant les scripts d'image de la première image (comme un constructeur avant tout autre code).
  • Il ne s'exécute que pendant la lecture ou le test : en pause ou en édition, rien ne tourne — mêmes règles que les scripts d'image.

2.3 Un Scene scopé au clip

Dans le script d'un MovieClip, la variable Scene (et son alias Game) ne désigne plus la scène racine mais ce clip :

API (dans un script de MovieClip)Effet
Scene.stop() / Scene.play()Arrête / relance ce clip seulement — les autres clips et la scène racine continuent.
Scene.currentFrameImage courante de la timeline du clip.
Scene.gotoAndPlay("Entry")Saut en utilisant les labels d'image du symbole (Timeline : champ label).
Scene.frameCountLongueur du clip.
Scene.onEnterFrame(fn)Boucle de jeu propre à ce clip : fn est appelée à chaque image avancée du clip. Un clip arrêté ne « tick » pas (sémantique Animate).
Scene.width/height/frameRatePropriétés du document (lecture seule).
Scene.log(...), Scene.random(n)Divers, identiques à la scène.
Exemple — un clip qui attend puis joue une séquence : 
// Constructeur du MovieClip : exécuté une fois par instance
Scene.stop();                       // ce clip démarre figé
Scene.onEnterFrame(function (f) {   // boucle propre au clip
  // ... détection, temporisation, etc.
  Scene.gotoAndPlay("explosion");   // label posé dans la timeline du symbole
});

2.4 Scène principale et scripts d'image

La scène principale se code comme toujours avec les scripts nommés du document (onglets du panneau Scripts, exécutés via le bouton Exécuter ou à la lecture) : leur Scene est la scène racine. Les scripts d'image (actions posées sur une image clé d'un calque) existent aussi par clip — un MovieClip enfant exécute les siens avec le même Scene scopé. Tous ces scripts sont externalisables de la même façon (section 3), seule la relecture automatique du bouton Lier est réservée aux scripts nommés et aux scripts de MovieClip (v1).

3. Le workflow fichiers externes

3.1 Les quatre boutons

Dans le panneau Scripts, une ligne apparaît sous les onglets (et sous le bouton MovieClip quand vous êtes dans un symbole). Elle s'applique au script en cours d'édition :

BoutonActionNavigateurs
ImporterChoisir un fichier .js sur le disque : son contenu remplace le code du script courant.Tous
ExporterTélécharger le code du script courant en <document>_<script>.js (ex : MonJeu_Hero.js).Tous
VS CodeOuvrir le fichier dans Visual Studio Code via le protocole vscode://. Le dossier local des scripts est demandé une seule fois puis mémorisé.Tous
LierLier le script à un fichier du disque : le contenu est relu automatiquement à chaque retour dans l'application (focus de la fenêtre), et via le bouton Recharger.Chrome, Edge, Vivaldi (Chromium)

3.2 Deux façons de travailler

Flux universel (tous navigateurs, y compris Firefox/Safari)

  1. Exporter le script : vous obtenez un fichier .js dans vos Téléchargements — rangez-le dans votre dossier de projet.
  2. VS Code : l'application ouvre le fichier dans VS Code (après le premier réglage du dossier).
  3. Vous modifiez, vous sauvegardez (Ctrl+S), vous revenez dans TweenJS.
  4. Importer le fichier modifié : le code du script est à jour dans l'application.

Flux lié (Chrome, Edge, Vivaldi) — recommandé

  1. Lier : choisissez le fichier .js une fois. Il devient la source de vérité de ce script.
  2. Modifiez-le dans VS Code (bouton VS Code), sauvegardez.
  3. Revenez simplement dans la fenêtre TweenJS : le contenu est relu tout seul. Le lien survit aux rechargements de la page (handle conservé en IndexedDB) ; après un rechargement, le navigateur demande de re-confirmer l'accès — le bouton Recharger sert à ça.
Bon à savoir. Le lien est mémorisé par script et par document (le nom du fichier lié s'affiche dans le panneau). Lier un nouveau fichier à un autre script ne casse pas les liens précédents : chaque script a le sien.

3.3 Configuration du dossier VS Code

Au premier clic sur VS Code, un dialogue demande le chemin du dossier où vous rangez vos scripts sur ce poste, par exemple :

Windows : C:\projets\tweenjs\scripts
Linux   : /home/vous/projets/tweenjs/scripts

Ce chemin est mémorisé dans le navigateur (localStorage, clé tweenjs.vscodeFolder) ; il est repris pour tous les scripts. Pour le changer, videz le localStorage ou appelez localStorage.removeItem('tweenjs.vscodeFolder') dans la console du navigateur, puis cliquez à nouveau sur VS Code.

4. Recette complète pas à pas

Objectif : un MovieClip Balle dont le comportement est codé dans balle.js sous VS Code, rebondissant en boucle pilotée par script.

  1. Créez le symbole : Bibliothèque → nouveau symbole MovieClip « Balle », dessinez la balle, posez éventuellement un label d'image "saut" sur l'image où elle saute.
  2. Entrez dans le symbole (double-clic) → panneau Scripts → bouton MovieClip : Balle : le squelette de constructeur est prêt.
  3. Complétez le code : 
    // balle.js — constructeur du MovieClip Balle
Scene.stop();
Scene.onEnterFrame(function (f) {
  // avance d'un pas à chaque image de la scène parente
  Scene.gotoAndPlay(Scene.currentFrame + 1);
});
  4. Externalisez : bouton Exporter → récupérez SansTitre_Balle.js et renommez-le balle.js dans votre dossier de scripts.
  5. Liez (Chrome/Edge/Vivaldi) : bouton Lier → sélectionnez balle.js. Le panneau affiche lié : balle.js.
  6. Sur la scène principale, posez deux instances de Balle (Nom d'instance balle1, balle2 dans les propriétés).
  7. Testez : lecture (Espace ou bouton) — chaque instance exécute son constructeur ; les instances nommées restent pilotables depuis le script de la scène (balle1.x += 1;).
  8. Itérez dans VS Code : modifiez balle.js, Ctrl+S, revenez dans TweenJS — le code est déjà à jour (flux lié), relancez la lecture.

5. Exports : le code suit toujours le projet

Le contenu d'un script externe est incrusté dans le document TweenJS au moment de l'import ou de la relecture du lien. Conséquence : tous les exports fonctionnent sans les fichiers .js :

ExportComportement
HTML autonome (menu Fichier)Les scripts de MovieClip sont embarqués dans les données du document exporté et exécutés pareillement : une fois par instance, Scene scopé au clip, avant les scripts d'image.
Objet de jeu (classe JS + runtime)Le script du symbole exporté est embarqué dans DATA : le constructeur de la classe l'exécute à la création.
JSON (sauvegarde)Le code des scripts fait partie du document : sauvegarde/chargement emportent tout.
Limite v1 — mode compilé. L'export « Compiler un HTML » (sans eval/new Function) n'exécute pas encore les scripts de MovieClip : le bloc dynamique est retiré à la compilation. Pour un projet qui utilise des scripts de clip, préférez l'export HTML classique.

6. Limites v1 et pistes v2

  • Scripts d'image : import/export externes fonctionnent, mais pas le lien vivant (v1) — le bouton Lier n'apparaît pas pour eux.
  • Firefox / Safari : pas de relecture automatique ; il faut ré-importer le fichier après chaque sauvegarde (flux universel).
  • Permissions après rechargement : le lien survit, mais le navigateur exige un clic (Recharger) pour redonner l'accès en lecture à un fichier lié.
  • Navigateur ≠ disque : le bouton VS Code ouvre l'éditeur, il ne peut pas pousser le code de l'application vers le fichier — c'est le bouton Exporter qui écrit le fichier.

Pistes d'évolution : lien vivant étendu aux scripts d'image ; export « projet complet vers un dossier » (File System Access API) ; autocomplétion de l'API clip dans l'éditeur intégré ; supervision par un petit serveur de développement local pour la relecture hors Chromium.

Récapitulatif express. Scène = scripts nommés du document · MovieClip = bouton « MovieClip : ... » (une exécution par instance, Scene scopé au clip) · coder dehors = Exporter → VS Code → sauvegarder → Importer (tous navigateurs) ou Lier (Chromium, relecture auto au focus) · les exports restent autonomes, le code est toujours incrusté.
