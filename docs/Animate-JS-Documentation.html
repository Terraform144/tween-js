1. Bien démarrer

Animate JS (projet TweenJS) est un éditeur d'animation vectorielle image par image, inspiré d'Adobe Animate/Flash : calques, images clés, interpolation de mouvement, morphing de courbes, symboles, ossature avec IK — le tout en JavaScript vanilla (Konva.js pour le rendu Canvas, Vite pour le build), sans framework.

1.1 Lancer l'application

npm install        « une seule fois »
npm run dev        « ouvre http://localhost:5173 »

Deux formes de l'application existent, mises à jour ensemble à chaque modification :

VersionOùUsage
Principalesrc/, servie par ViteDéveloppement, build dist/
PureVanillaAnimate_JS_PureVanilla/ (HTML + bundle statiques)Déploiement statique, aucune dépendance CDN (Konva et CreateJS sont des copies locales dans libs/)

100 % Vanilla JS, 100 % sans serveur. Le site n'a besoin d'aucun backend : tout (HTML, CSS, JavaScript, bibliothèques, APK) est servi sous forme de fichiers statiques. Vous pouvez copier le dossier du site tel quel — sur une clé USB, un autre ordinateur, un hébergement simple — et il fonctionnera à l'identique, même hors ligne.

1.2 Créer sa première animation en 60 secondes

  1. Sélectionne l'outil Rectangle (R) et dessine un carré sur la scène.
  2. Dans la timeline, clique une cellule plus loin (ex. image 12) et appuie sur F6 : nouvelle image clé contenant le carré.
  3. Déplace le carré ailleurs sur la scène, puis clique le bouton ⇄ de l'image clé 1 : interpolation de mouvement.
  4. Espace : lecture. Le carré glisse.
Tout repose sur trois idées. (1) Un document = des calques d'images clés contenant des éléments (formes, instances de symboles, images, texte). (2) Entre deux images clés avec tween, tout s'interpole. (3) Les scripts pilotent le document pendant la lecture.

2.2 Barre d'outils

Suivent les couleurs de remplissage/contour, la taille du pinceau, le zoom et l'outil main (pan). La scène s'adapte à l'écran (mobile/tablette inclus) et passe en plein écran.

2.3 Timeline

  • Calques : visibilité, verrouillage, renommage, ajout/suppression.
  • Images clés : F6 image clé, F7 image clé vide, Espace lecture/pause, scrub sur la règle.
  • Interpolation : bouton ⇄ sur une image clé — position, rotation, échelle, opacité, couleurs ; 4 courbes d'accélération (Propriétés).
  • Morphing : si une courbe tweenée a le même nombre de points sur l'image clé suivante, elle se déforme point à point.
  • Étiquette : champ pour nommer une image (ex. Start) — utilisable avec gotoAndPlay("Start").
  • Script d'image : un calque peut porter du code exécuté quand la tête de lecture atteint cette image (comportement Animate CC : en lecture seulement).

2.4 Bibliothèque et symboles

  • Sélectionner des objets puis F8 : Convertir en symbole — type Graphic (synchro sur le parent) ou MovieClip (timeline indépendante, scripts propres).
  • Double-clic sur une instance (ou un élément de la bibliothèque) : édition du symbole en mode isolé.
  • Glisser un élément de la bibliothèque sur la scène : nouvelle instance. Deux instances du même symbole jouent indépendamment.
  • Bouton d'export « objet de jeu » sur un symbole : voir chapitre 8.

2.5 Panneau Propriétés

Contextuel à la sélection : Nom d'instance, X/Y, dimensions, rotation, échelle, opacité, remplissage/contour, texte (taille, interligne, alignement). Pour les MovieClips : squelette de skinning. Le Nom d'instance est la clé des scripts : c'est lui qui devient une variable.

Simplification de forme : pour les formes de type ligne ou tracé (Plume), le panneau propose deux boutons :

  • Simplifier la forme : applique une simplification avec tolérance par défaut (1.0) pour réduire le nombre de points tout en conservant la silhouette.
  • Tolérance + Simplifier avec : choisis une tolérance personnalisée (plus élevée = moins de points conservés) avant simplification.

L'algorithme utilisé est Ramer-Douglas-Peucker (RDP) : les points dont la distance à la nouvelle ligne est inférieure à la tolérance sont supprimés. Les extrémités sont toujours conservées. Idéal pour optimiser les tracés complexes exportés depuis Inkscape ou illustrator. L'algorithme complet et l'API simplifyPathPoints sont détaillés au chapitre 10.

2.6 Panneau Scripts

Éditeur CodeMirror avec plusieurs scripts nommés par onglets, boutons Exécuter (Ctrl+Entrée) et Arrêter, et une console de sortie. Le bouton « image » cible le script d'une image précise de la timeline. Le script propre à chaque MovieClip et le workflow d'édition dans VS Code (fichiers .js externes, lien vivant) sont détaillés au chapitre 9.

3. Les scripts : le contrat

3.1 Qui voit quoi

Un script est compilé et exécuté avec cinq paramètres — c'est tout ce qu'il voit :

Scene  Game  console  named  createjs
ParamètreContenu
Scene / GameL'API de pilotage (alias l'un de l'autre) : lecture, dimensions, création d'éléments, événements
consoleConsole (sortie visible dans le panneau)
namedMap des instances nommées de l'image courante : named["But"]
createjsLa bibliothèque CreateJS complète (EaselJS, TweenJS, SoundJS, PreloadJS) chargée en local

Chaque instance nommée est de plus injectée comme variable directe : écrire But.x += 1 fonctionne sans déclaration.

Mode strict. Les scripts s'exécutent en "use strict" : this vaut undefined au niveau supérieur — n'écris pas this.But, écris But.

3.2 Quand un script s'exécute

  • Scripts nommés (onglets) : au clic sur Exécuter. Chaque Exécuter repart de zéro (les inscriptions d'événements précédentes sont retirées).
  • Scripts d'image : automatiquement quand la lecture atteint l'image, à chaque passage.
  • Les événements de souris ne se déclenchent qu'en lecture : en édition, le clic appartient aux outils.

3.3 L'API Scene (essentiel)

Scene.width / Scene.height / Scene.frameRate / Scene.frameCount / Scene.backgroundColor
Scene.play() / Scene.stop()
Scene.gotoAndPlay(frameOuLabel) / Scene.gotoAndStop(frameOuLabel)   // ex. gotoAndStop("Start")
Scene.currentFrame / Scene.playing / Scene.keys
Scene.onEnterFrame(cb) / Scene.onKeyDown(cb) / Scene.onKeyUp(cb) / Scene.onClick(...)
Scene.addShape(type, props) / Scene.addInstance(symbolId, props)
Scene.log(...) / Scene.random(n)
Règle d'or des handlers. Les inscriptions (But.on("click", ...)) se font une seule fois, au niveau supérieur du script — jamais dans onEnterFrame, sous peine d'empilement. Les handlers posés par Exécuter survivent aux scripts d'image ; les handlers posés par un script d'image sont purgés entre ses passages.

3.4 Le quadri-diagnostic (à connaître par cœur)

Scene.log("createjs :", typeof createjs);
Scene.log("nommes :", Object.keys(named).join(", ") || "AUCUN");
Scene.log("But typeof:", typeof But);
Scene.log("playing:", Scene.playing);

Quand quelque chose ne réagit pas, ces quatre lignes éliminent 90 % des causes : bibliothèque absente, instance invisible à cette image, nom mal orthographié, lecture arrêtée.

4. Exploiter CreateJS dans les scripts

La bibliothèque CreateJS complète est disponible sous la variable createjs — copie locale (dossier libs/createjs, licence MIT), aucune connexion requise.

4.1 TweenJS : les interpolations programmées

createjs.Tween.get(cible)              // cible : un élément nommé, ou tout objet
  .to({ x: 300, rotation: 180 }, 1000)  // 1 seconde
  .wait(300)                            // pause 300 ms
  .to({ y: 200 }, 500, createjs.Ease.bounceOut)
  .call(function () { Scene.log("fini !"); });
ObjetUsage
createjs.TweenSéquences d'interpolation ; .get(cible), .to(props, ms, ease), .wait(ms), .call(fn), removeTweens(cible)
createjs.EaseCourbes : linear, quadOut, cubicInOut, bounceOut, elasticOut, …
createjs.TickerHorloge à ~60 Hz. Mis en pause avec l'éditeur : les tweens s'arrêtent quand tu arrêtes la lecture. e.delta en ms dans le callback.
createjs.SoundSons (Sound.registerSound, Sound.play)
createjs.LoadQueueChargement de fichiers (images, sons, JSON)
Pourquoi c'est fluide. Le document tourne à son frameRate (ex. 24 fps) mais le rendu se fait à chaque frame d'affichage (~60 fps) : un tween CreateJS reste parfaitement lisse, même si la timeline est lente.

4.2 Exemples éclair

// Clignotement piloté par le Ticker (60 fps)
createjs.Ticker.addEventListener("tick", function (e) {
  lampe.opacity = 0.5 + 0.5 * Math.sin(e.delta * 0.01);
});

// Chaîne : approche puis rebond
createjs.Tween.get(Balle)
  .to({ x: 400 }, 800, createjs.Ease.quadIn)
  .to({ x: 0 }, 1200, createjs.Ease.bounceOut);

5. Événements et interactions

5.1 Sur une instance nommée (sémantique EaselJS)

But.on("click", function (ev) {
  Scene.log("clic en", ev.stageX, ev.stageY, "sur", ev.target.name);
});
ÉvénementÉmis quand
clickDown et up sur le même élément (règle CreateJS)
mousedown / mouseup / dblclickSur l'élément sous le curseur
pressmove / pressupSur l'élément pressé — pendant et après la pression (base du glisser-déposer)
mouseover/out, rollover/rolloutEntrée/sortie du survol
tickÀ chaque image de lecture

Également : off/removeEventListener, removeAllEventListeners, hasEventListener, dispatchEvent. Sur Scene : stagemousedown/stagemousemove/stagemouseup/stageclick (tout clic, même dans le vide) et tick.

5.2 Scene.onClick — la version rapide

Scene.onClick(function (x, y) { ... });        // tout clic sur la scène
Scene.onClick("But", function (x, y, el) { ... }); // clic sur l'instance nommée

5.3 Où peut-on cliquer ? (hit-testing)

  • Ellipse : le disque réel, pas la boîte englobante.
  • Rect, texte, image : boîte englobante ; rotation et échelle prises en compte.
  • Ligne/chemin : boîte des points.
  • Instance de symbole : enveloppe de tout ce que dessine le symbole (toutes ses images). Un symbole vide n'est cliquable nulle part.
  • Les éléments d'un calque tweené sont testés à la position de leur image clé (approximation).

5.4 Navigation par labels

Scene.gotoAndPlay("Menu");
But.on("click", function () { Scene.gotoAndStop("Start"); });

Les labels se posent dans la timeline (champ Étiquette). Un label introuvable produit un avertissement console et aucun déplacement. Dans un script posé à l'intérieur d'un MovieClip, les labels résolus sont ceux du symbole.

6. Recettes prêtes à tester

Pour chaque recette : nomme une instance comme indiqué (champ « Nom d'instance » des Propriétés), colle le code dans le panneau Scripts, Exécute, et mets la lecture.

Recette 1 — Diagnostic universel

Scene.log("createjs :", typeof createjs);
Scene.log("nommes :", Object.keys(named).join(", ") || "AUCUN");
Scene.play();

Résultat : la console affiche l'état du contrat. Aucune condition.

Recette 2 — Bouton de section (le patron « menu »)

Scene.play();
But.on("click", function () {
  Scene.gotoAndStop("Start");
});

Résultat : au clic sur l'instance But (pendant la lecture), la tête de lecture saute à l'image étiquetée Start et s'y arrête. Variante visuelle : change But.scaleX/Y à mousedown et remets à 1 à pressup.

Recette 3 — Glisser-déposer borné

Scene.play();
var off = null;
But.on("mousedown", function (ev) { off = { dx: But.x - ev.stageX, dy: But.y - ev.stageY }; });
But.on("pressmove", function (ev) {
  if (!off) return;
  But.x = Math.max(0, Math.min(Scene.width,  ev.stageX + off.dx));
  But.y = Math.max(0, Math.min(Scene.height, ev.stageY + off.dy));
});
But.on("pressup", function () { off = null; });

Résultat : l'instance suit le doigt/souris sans sauter au centre, et ne sort jamais de la scène.

Recette 4 — Déplacement au clavier

Scene.play();
Scene.onEnterFrame(function () {
  var v = 6;
  if (Scene.keys["ArrowLeft"])  Perso.x -= v;
  if (Scene.keys["ArrowRight"]) Perso.x += v;
  if (Scene.keys["ArrowUp"])    Perso.y -= v;
  if (Scene.keys["ArrowDown"])  Perso.y += v;
});

Résultat : l'instance Perso bouge aux flèches pendant la lecture. (La saisie dans les panneaux est ignorée automatiquement.)

Recette 5 — Tween CreateJS avec suite logique

Scene.play();
createjs.Tween.get(Balle)
  .to({ x: 400 }, 800, createjs.Ease.quadIn)
  .to({ x: 0 }, 1200, createjs.Ease.bounceOut)
  .call(function () { Scene.log("Terminé, retour au départ"); });

Résultat : la balle accélère vers la droite puis rebondit au retour, et la console confirme la fin.

Recette 6 — Compteur de score avec tick

Scene.play();
var score = 0;
Score.on("tick", function () {
  score = score + 1;
  Score.text = "Score : " + score;
});

Résultat : une instance de texte nommée Score s'incrémente à chaque image de lecture. (Remarque : le handler est posé par Exécuter, il survit aux scripts d'image.)

Recette 7 — Élément qui suit la souris

Scene.play();
Scene.on("stagemousemove", function (ev) {
  Viseur.x = ev.stageX;
  Viseur.y = ev.stageY;
});

Résultat : l'instance Viseur se colle au curseur pendant la lecture.

Recette 8 — Menu complet (trois boutons)

Scene.play();
B1.on("click", function () { Scene.gotoAndStop("Jeu"); });
B2.on("click", function () { Scene.gotoAndStop("Score"); });
B3.on("click", function () { Scene.gotoAndStop("Options"); });

Résultat : chaque bouton saute à sa section. Un bouton « Retour » posé sur chaque section peut être la même instance nommée Retour pointant vers "Menu".

7. Exporter : JSON, HTML, compilé

FormatContenuQuand l'utiliser
Enregistrer JSON / Ouvrir…Le projet completSauvegarde, reprise de travail
Exporter HTMLUn fichier HTML autonome qui rejoue l'animation, avec les scripts (exécutés dynamiquement) ; CreateJS inliné si un script l'utilisePartager une animation jouable, l'intégrer quelque part

Objet de jeu (bouton sur un symbole)tween-runtime.js + une classe JS par symboleChapitre 8 — intégrer dans votre propre jeu
Exporter PNG (ZIP)Un ZIP avec une image PNG par frame (frame_0001.png, frame_0002.png...), à la taille du documentMonter la séquence dans un logiciel de montage, un moteur de jeu, ou retoucher image par image
L'export PNG capture l'animation « pure ». Chaque image est rendue exactement comme pendant la lecture : tweens, morphing, caméra de scène interpolée, et les MovieClips imbriqués avancent d'une frame à chaque image de la séquence. Les scripts, en revanche, ne sont pas exécutés — un script qui déplace des objets à l'exécution n'apparaîtra pas dans les images. Le fond de la scène (backgroundColor) est inclus dans chaque PNG.
Parité. Les deux exports HTML se comportent comme l'éditeur : mêmes événements (clics en lecture), mêmes labels, même Scene.onClick. L'export classique exécute vos scripts dynamiquement (comme l'éditeur) ; le compilé les a transformés en fonctions réelles — ouvrez-le dans un éditeur de texte, votre code y est lisible.

8. Utiliser un MovieClip dans votre propre jeu

C'est la sortie pensée pour les développeurs : animez un personnage dans Animate JS (labels « walk », « jump »…), exportez-le, et pilotez-le depuis votre code JavaScript, dans n'importe quelle page ou moteur de jeu.

8.1 Exporter

  1. Clique le bouton « objet de jeu » sur le symbole dans la bibliothèque.
  2. Deux fichiers sont téléchargés : tween-runtime.js (le moteur, aucune dépendance) et MonPerso.js — une classe qui embarque les données du symbole et de tout ce dont il dépend.
// MonPerso.js — généré par Animate JS
import { MovieClip } from './tween-runtime.js';

const DATA = { /* ...calques, images clés, labels, bitmaps... */ };

export class MonPersoClip extends MovieClip {
  constructor(props) { super(DATA, props); }
}
// Labels disponibles pour gotoAndPlay()/gotoAndStop() : "walk", "jump"

8.2 L'API MovieClip

MembreRôle
x, y, rotation, scaleX, scaleY, opacity, visible, loopTransformations — modifiables à tout moment
play() / stop()Lecture de la timeline du clip
gotoAndPlay(frameOuLabel) / gotoAndStop(frameOuLabel)Saut direct (numéro ou label)
currentFrame / frameCount / isPlayingÉtat (lecture seule)
update(dt)Avance l'animation — dt en millisecondes ; à appeler une fois par frame de jeu
draw(ctx)Dessine sur un contexte Canvas 2D — après update
addEventListener("loop" / "complete", fn)Boucle terminée / fin de lecture sans boucle
imbriquésLes MovieClips enfants ont leur propre timeline et avancent avec le parent

8.3 Exemple complet — page de jeu autonome

<!doctype html>
<html lang="fr">
<body>
<canvas id="jeu" width="640" height="480"></canvas>
<script type="module">
  import { MonPersoClip } from './MonPerso.js';

  const canvas = document.getElementById('jeu');
  const ctx = canvas.getContext('2d');

  const perso = new MonPersoClip({ x: 100, y: 300 });
  perso.gotoAndPlay('walk');                 // label posé dans l'éditeur

  perso.addEventListener('complete', function () {
    console.log('Animation terminée (loop = false)');
  });

  addEventListener('keydown', function (e) {
    if (e.key === ' ') perso.gotoAndPlay('jump');  // Espace : saut
  });

  let last = null;
  function gameLoop(t) {
    requestAnimationFrame(gameLoop);
    if (last === null) last = t;
    const dt = t - last;                    // ms
    last = t;

    perso.update(dt);                       // 1. faire avancer l'animation
    perso.x += 1;                           // 2. votre logique de jeu
    ctx.clearRect(0, 0, canvas.width, canvas.height);
    perso.draw(ctx);                        // 3. dessiner
  }
  requestAnimationFrame(gameLoop);
</script>
</body>
</html>
Les trois règles d'intégration. (1) dt est en millisecondes. (2) Un seul update(dt) par frame, draw(ctx) juste après. (3) Chaque instance a son état propre : créez deux new MonPersoClip() pour deux ennemis indépendants.

9. Coder avec TweenJS : script de MovieClip et éditeur de code externe

9.1 Le principe général

Dans Adobe Animate CC, les gros projets ActionScript 3 reposent sur une séparation nette : l'éditeur visuel s'occupe du dessin et de la timeline, et le code vit dans des fichiers .as séparés, édités dans un vrai éditeur de code. TweenJS reprend cette séparation :

  • Le panneau Scripts de l'application reste le point d'entrée : c'est lui qui détient le code de chaque script et qui l'exécute pendant la lecture.
  • Chaque script (celui de la scène principale comme celui de chaque MovieClip) peut être externalisé dans un fichier .js que vous éditez où vous voulez — typiquement dans Visual Studio Code.
  • Les boutons Importer, Exporter, VS Code et Lier du panneau Scripts font la navette entre votre éditeur et l'application.
Ce qu'un navigateur peut et ne peut pas faire. Une application web ne peut ni lancer un programme de votre poste, ni surveiller un dossier du disque en arrière-plan. TweenJS contourne honnêtement ces limites avec trois mécanismes universels (import de fichier, téléchargement, protocole vscode:// de VS Code) et un mécanisme avancé — la relecture automatique — réservé aux navigateurs Chromium (Chrome, Edge, Vivaldi) via la File System Access API.

9.2 Le script de MovieClip : votre « classe AS3 »

9.2.1 Où le trouver

Chaque symbole de type MovieClip possède son propre script — l'équivalent d'une classe AS3 attachée au clip. Pour l'éditer :

  1. Dans la Bibliothèque, double-cliquez le MovieClip pour entrer dans son contexte d'édition (ou ouvrez une instance sur scène et double-cliquez-la).
  2. Dans le panneau Scripts, un bouton MovieClip : <nom> apparaît (entre les onglets de scripts et les scripts d'image).
  3. Cliquez dessus : l'éditeur de code bascule sur le script du symbole, prérempli avec un squelette de constructeur.

9.2.2 Quand s'exécute-t-il ?

Le script de MovieClip est un constructeur d'instance :

  • Il s'exécute UNE seule fois par instance, au démarrage de la lecture — deux instances du même symbole exécutent chacune le script, avec un état indépendant.
  • Il s'exécute avant les scripts d'image de la première image (comme un constructeur avant tout autre code).
  • Il ne s'exécute que pendant la lecture ou le test : en pause ou en édition, rien ne tourne — mêmes règles que les scripts d'image.

9.2.3 Un Scene scopé au clip

Dans le script d'un MovieClip, la variable Scene (et son alias Game) ne désigne plus la scène racine mais ce clip :

API (dans un script de MovieClip)Effet
Scene.stop() / Scene.play()Arrête / relance ce clip seulement — les autres clips et la scène racine continuent.
Scene.currentFrameImage courante de la timeline du clip.
Scene.gotoAndPlay("Entry")Saut en utilisant les labels d'image du symbole (Timeline : champ label).
Scene.frameCountLongueur du clip.
Scene.onEnterFrame(fn)Boucle de jeu propre à ce clip : fn est appelée à chaque image avancée du clip. Un clip arrêté ne « tick » pas (sémantique Animate).
Scene.width/height/frameRatePropriétés du document (lecture seule).
Scene.log(...), Scene.random(n)Divers, identiques à la scène.
Exemple — un clip qui attend puis joue une séquence : 
// Constructeur du MovieClip : exécuté une fois par instance
Scene.stop();                       // ce clip démarre figé
Scene.onEnterFrame(function (f) {   // boucle propre au clip
  // ... détection, temporisation, etc.
  Scene.gotoAndPlay("explosion");   // label posé dans la timeline du symbole
});

9.2.4 Scène principale et scripts d'image

La scène principale se code comme toujours avec les scripts nommés du document (onglets du panneau Scripts, exécutés via le bouton Exécuter ou à la lecture) : leur Scene est la scène racine. Les scripts d'image (actions posées sur une image clé d'un calque) existent aussi par clip — un MovieClip enfant exécute les siens avec le même Scene scopé. Tous ces scripts sont externalisables de la même façon (section 9.3), seule la relecture automatique du bouton Lier est réservée aux scripts nommés et aux scripts de MovieClip (v1).

9.3 Le workflow fichiers externes

9.3.1 Les quatre boutons

Dans le panneau Scripts, une ligne apparaît sous les onglets (et sous le bouton MovieClip quand vous êtes dans un symbole). Elle s'applique au script en cours d'édition :

BoutonActionNavigateurs
ImporterChoisir un fichier .js sur le disque : son contenu remplace le code du script courant.Tous
ExporterTélécharger le code du script courant en <document>_<script>.js (ex : MonJeu_Hero.js).Tous
VS CodeOuvrir le fichier dans Visual Studio Code via le protocole vscode://. Le dossier local des scripts est demandé une seule fois puis mémorisé.Tous

9.3.2 Deux façons de travailler

10. Simplification de forme (Ramer-Douglas-Peucker)

10.1 Le problème à résoudre

Un tracé dessiné à la Plume ou importé depuis un SVG contient souvent des points d'ancrage redondants : des sommets presque alignés qui n'apportent rien à la silhouette visuelle mais alourdissent le document. Le but de la simplification est double :

  • réduire le nombre de points (fichier plus léger, édition plus simple) ;
  • garder la forme reconnaissable — la silhouette simplifiée doit rester dans un rayon ε (la tolérance) de la forme d'origine.

Dans l'éditeur, la fonctionnalité se présente dans le Panneau Propriétés d'une forme de type ligne ou tracé sélectionnée : un bouton « Simplifier la forme » (tolérance 1.0 par défaut) et un champ Tolérance avec le bouton « Simplifier avec » pour choisir son ε.

10.2 Pourquoi Ramer-Douglas-Peucker

Plusieurs familles d'algorithmes existent pour décimer une polyligne. Le choix s'est porté sur Ramer-Douglas-Peucker (RDP, 1973) pour trois raisons :

  1. Garantie mathématique : tout point supprimé se retrouve à une distance ≤ ε du contour simplifié. L'erreur visuelle est donc bornée par construction, ce qui n'est pas le cas des méthodes de décimation par pas (garder 1 point sur N) ou des seuils d'angle.
  2. Extrémités conservées : le premier et le dernier point d'un tracé ouvert ne sont jamais supprimés — indispensable pour que les tracés raccordés à d'autres restent raccordés.
  3. Simplicité : une vingtaine de lignes récursives, aucun état, aucune dépendance, testable sous Node.
    4. Performance. RDP est en O(n log n) en moyenne et O(n²) au pire cas (points répartis uniformément). Pour des tracés d'éditeur (quelques centaines de points au plus), c'est instantané.

    L'implémentation est un portage adapté de simplify.js du projet __IIB.v.3 (lissé + RDP, testé unitairement), réécrite pour manipuler directement les PathPoint de ce projet — voir section 10.5.

    10.3 Le cœur de l'algorithme

    10.3.1 La distance point-segment (et pas point-droite)

    La brique de base est la distance entre un point P et le segment AB — pas la droite infinie AB. Un point situé « après » B doit être mesuré par rapport à B, pas projeté au-delà :

    function distToSeg(px, py, ax, ay, bx, by) {
  const dx = bx - ax, dy = by - ay;
  const l2 = dx * dx + dy * dy;
  let t = l2 ? ((px - ax) * dx + (py - ay) * dy) / l2 : 0;
  t = Math.max(0, Math.min(1, t));          // projection clampée sur [0,1]
  return Math.hypot(px - (ax + t * dx), py - (ay + t * dy));
}

    Le paramètre t projette P sur la droite AB ; le clamp garantit que la mesure tombe sur le segment. Cas dégénéré l2 = 0 (A et B confondus) : la distance est simplement celle de P à A.

    10.3.2 La récursion RDP (tracé ouvert)

    Le principe : entre les extrémités A et B du tracé, on tend une « corde ». On cherche le point le plus éloigné de cette corde :

    • si dmax > ε : ce point est un sommet significatif — on le garde, et on relance la récursion sur les deux sous-tronçons [A..point] et [point..B] ;
    • si dmax ≤ ε : tous les points intermédiaires sont remplacés par le segment droit AB.
    function rdpOpen(pts, eps) {
  if (pts.length < 3) return [...pts];
  const A = pts[0], B = pts[pts.length - 1];
  let dmax = -1, index = -1;
  for (let i = 1; i < pts.length - 1; i++) {
    const d = distToSeg(pts[i].x, pts[i].y, A.x, A.y, B.x, B.y);
    if (d > dmax) { dmax = d; index = i; }
  }
  if (dmax > eps) {
    const left  = rdpOpen(pts.slice(0, index + 1), eps);
    const right = rdpOpen(pts.slice(index), eps);
    return left.slice(0, -1).concat(right);   // le point pivot est partagé
  }
  return [A, B];
}
    Concrètement : une succession de points alignés s'effondre en 2 extrémités ; un « pic » qui dépasse ε de la corde survit et devient un sommet. Plus ε est grand, plus il faut de l'ampleur pour survivre — d'où le réglage par le champ Tolérance.

    10.3.3 Le cas fermé : découper l'anneau

    Un contour fermé (rempli) n'a pas d'extrémités naturelles : la récursion ouverte n'a pas de corde évidente sur laquelle s'appuyer. La solution :

    1. prendre le point 0 et le point k le plus éloigné de lui (une approximation du « diamètre » de la forme, en O(n)) ;
    2. cette paire découpe l'anneau en deux chaînes ouvertes : [0..k] et [k..0] ;
    3. appliquer rdpOpen sur chacune, puis recoller les résultats en retirant les doublons aux jointures.
    function rdpClosed(ring, eps) {
  const n = ring.length;
  if (n < 5) return [...ring];
  // point le plus éloigné du point 0
  let k = 1, dmax = -1;
  for (let i = 1; i < n; i++) { /* ... */ }
  const ra = rdpOpen(ring.slice(0, k + 1), eps);
  const rb = rdpOpen(ring.slice(k).concat([ring[0]]), eps);
  const out = ra.slice(0, -1).concat(rb.slice(0, -1));
  return out.length >= 3 ? out : [...ring];   // garde-fou : ≥ 3 sommets
}

    Le garde-fou final garantit qu'un polygone fermé ne descend jamais sous 3 points — sous peine de ne plus rien délimiter.

    10.3.4 Le lissage préalable (optionnel)

    Avant la décimation, l'API accepte smoothPasses passes de moyenne mobile pondérée (poids 1-2-1 sur les voisins, normalisés par 4) :

    q[i] = (p[i-1] + 2*p[i] + p[i+1]) / 4
    • Chaîne ouverte : les extrémités restent figées, seuls les points intérieurs bougent ;
    • Anneau : la moyenne est cyclique (wrap-around), le point 0 a pour voisins les points n-1 et 1.
    Choix de l'éditeur. Le panneau Propriétés appelle la simplification avec smoothPasses = 0 : aucun point n'est déplacé, seuls des points redondants disparaissent. Le lissage est disponible dans l'API (simplifyPathPoints(pts, ε, fermé, passes)) pour un usage futur — par exemple lisser un tracé au pinceau avant de le simplifier.

    10.4 Adaptation aux courbes de l'éditeur

    C'est la partie où l'algorithme générique rencontre le modèle de données du projet. Un point d'ancrage de tracé n'est pas un simple [x, y] :

    { x, y, cIn, cOut, smooth }
    • x, y — position de l'ancre, relative à l'origine de la forme (shape.x/y) ;
    • cIn, cOut — vecteurs des poignées de Bézier, relatifs à l'ancre (ou null : point anguleux) ;
    • smooth — l'outil sous-sélection déplace alors cIn et cOut en miroir.

    10.4.1 La décision clé : les poignées sont supprimées

    Le point le plus important de l'implémentation : les points conservés par RDP perdent leurs poignées (cIn = cOut = null, smooth = false), et le tracé simplifié devient une polyligne d'ancres. Pourquoi ce choix :

    1. RDP classifie les points en « sommet significatif / point redondant ». Les anciennes poignées décrivaient la courbure du tracé d'origine : réattacher telles quelles des poignées pensées pour d'autres voisins produirait des arcs incohérents (des boucles, des dépassements) sur la nouvelle polyligne.
    2. Calculer de nouvelles poignées fidèles serait un problème de fitting de courbe (cf. pistes d'amélioration) — un algorithme différent, itératif, hors du périmètre de cette fonctionnalité.
    3. La garantie de RDP porte sur les ancres : tout point supprimé est à ≤ ε de la polyligne joignant les ancres conservées. La promesse « la silhouette ne bouge pas de plus de ε » reste ainsi exacte et vérifiable.
    Conséquence visuelle : sur un tracé très courbé, une tolérance élevée remplace des arcs par des segments légèrement anguleux. C'est le compromis explicite de la fonction : ε contrôle le rapport « nombre de points vs rondeur ». Une tolérance fine (0.3–0.5) ne touche que le bruit redondant et préserve la sensation de courbe.

    10.4.2 Ce qui ne bouge pas

    • Les points étant relatifs à l'origine de la forme, la simplification ne modifie ni shape.x/y, ni la position apparente de l'objet sur la scène ;
    • shape.closed pilote la variante d'algorithme (anneau ou chaîne ouverte) ;
    • toutes les autres propriétés (remplissage, contour, opacité, calque...) sont inchangées — seule la liste points est remplacée.

    10.5.1 Intégration dans le panneau Propriétés

    • Les contrôles n'apparaissent que pour une forme line ou path avec au moins 2 points ;
    • la mutation passe par mutateSelectedElement() → elle est annulable (Ctrl+Z) et posée sur l'image clé courante comme toute édition ;
    • si la tolérance ne retire aucun point, un message l'explique au lieu de semblant ne rien faire ;
    • en cas de résultat sous le minimum (tracé trop court), la fonction renvoie le tracé d'origine sans ses poignées — jamais un tracé invalide.

    10.6 Bien choisir sa tolérance

    ToléranceEffetUsage typique
    0.3 – 0.5Ne retire que les points quasi redondantsNettoyage fin, préparation au morphing
    1 – 2Équilibre points / fidélité (défaut : 1.0)Simplification standard d'un tracé Plume
    3 – 5Forte décimation, arcs → segments visiblesSilhouettes volontairement anguleuses, allègement massif
    > 5Seules les grandes aspérités surviventRéduire une courbe à son « squelette »
    Le bonus morphing. Le morphing de l'éditeur apparie les points par index (1er avec 1er, 2e avec 2e...) et ne se déclenche que si deux images clés contiennent le même nombre de points. Simplifier deux courbes avec la même tolérance tend à aligner leurs densités de points — et surtout, une courbe simplifiée est plus facile à retoucher à l'outil sous-sélection pour tomber exactement sur le bon compte avant de créer l'image clé suivante.

    10.7 Pistes d'amélioration

    • Fitting de Bézier (Schneider, 1990) : au lieu de conserver les ancres telles quelles, ajuster des segments de Bézier cubiques sur les points supprimés — la forme simplifiée resterait courbe. C'est l'évolution naturelle si les polylignes anguleuses deviennent gênantes ;
    • Tolérance relative : exprimer ε en pourcentage de la boîte englobante du tracé, pour qu'un même réglage « se sente pareil » sur une petite et une grande forme ;
    • Shape hints : laisser l'utilisateur épingler des points qui ne doivent jamais être supprimés (appariement de morphing guidé, comme dans Animate CC) ;
    • Prévisualisation : un curseur montrant en direct le résultat et le nombre de points conservés avant de valider.

    • Peau d'oignon (onion skin) : bouton dans la barre de la timeline + deux champs (nb passé / nb futur). Les images voisines de la tête de lecture s'affichent sous la scène — bleues vers le passé, rouges vers l'avenir, opacité dégressive. Édition seulement ; mémorisé d'une session à l'autre.

    • Copier/coller entre fenêtres-projets : Ctrl+C / Ctrl+X / Ctrl+V avec un presse-papiers partagé entre toutes les fenêtres ouvertes ; les images (assets) et symboles référencés sont importés automatiquement dans le projet cible.

    • Dégradés (linéaire / radial) : ligne « Dégradé » dans le panneau Propriétés de la forme (et uniquement là) : type, coordonnées en fraction de la boîte, stops de couleur éditables (offset, couleur, ∅ transparent, +/✕). Interpolés dans les tweens, rendus à l'identique dans l'éditeur et les exports.
    • CreateJS dans les scripts : testé — TweenJS, EaselJS (Stage/Shape/Text), PreloadJS (LoadQueue), Ticker et EventDispatcher fonctionnent dans la boîte de script. createjs.Sound est embarqué mais son plugin audio ne s'active pas de façon fiable selon les navigateurs : préférez Scene.playSound(...).
    • Grille + snap + règles : barre de la timeline — bouton grille (espacement réglable en px), bouton aimant (les déplacements et créations s'arrondissent à la grille), bouton règles. Règles graduées en haut/à gauche de la scène (pas adaptatif au zoom) ; glisser depuis une règle pose un guide (tireté orange, persisté dans le JSON, clic droit sur le guide pour le supprimer).
